Lecture 05 · C++14

Rule of Three

destructor copy constructor copy assignment deep copy

Overview

The Rule of Three is a C++ design guideline: if a class explicitly defines any one of the following three special member functions, it almost certainly needs to define all three:

  1. Destructor (~T())
  2. Copy constructor (T(const T&))
  3. Copy assignment operator (T& operator=(const T&))

The reason is simple: if you needed a custom destructor, your class is probably managing a resource (raw memory, a file handle, a network socket). The compiler-generated copy operations perform a shallow copy — they copy the pointer, not what it points to — which leads to double-frees, dangling pointers, and data corruption.

Notes

Shallow Copy vs Deep Copy

The compiler-generated copy constructor and copy assignment do a member-wise copy. For pointer members, this means both the original and the copy point to the same heap allocation. When either object is destroyed, the memory is freed — and the other object is left with a dangling pointer. A deep copy allocates new storage and copies the pointed-to data, so each object owns its own copy.

The Destructor

Responsible for releasing any resources the object acquired during its lifetime. If a class manages raw heap memory (new/delete), the destructor must call delete (or delete[] for arrays).

Copy Constructor

Called when an object is initialised from another object of the same type: 

T b = a;       // copy constructor
T c(a);        // copy constructor
void f(T x);   // copy constructor when passing by value

A correct copy constructor performs a deep copy — allocating new resources and copying the content.

Copy Assignment Operator

Called when an already-constructed object is assigned from another: 

T a, b;
a = b;         // copy assignment

Three responsibilities:

  1. Self-assignment guard: if (this == &rhs) return *this;
  2. Release the current resource before overwriting the pointer.
  3. Deep copy the new resource from rhs.

Copy-and-swap idiom: An elegant alternative — implement assignment by constructing a temporary copy and swapping with it. Automatically handles self-assignment and provides strong exception safety.

Code Examples

The Problem: Shallow Copy

#include <iostream>
#include <cstring>

class BadString {
    char* data;
public:
    BadString(const char* s) {
        data = new char[std::strlen(s) + 1];
        std::strcpy(data, s);
    }
    ~BadString() { delete[] data; }  // destructor defined...
    // ...but no copy constructor or copy assignment!
    // The compiler generates shallow copies.

    void print() const { std::cout << data << "\n"; }
};

int main() {
    BadString a("hello");
    BadString b = a;      // shallow copy: b.data == a.data (same pointer!)
    b.print();            // "hello"
    // When main exits: ~BadString() called for b, then for a
    // → double delete[] on the same pointer → undefined behaviour
}

The Fix: Rule of Three

#include <iostream>
#include <cstring>
#include <stdexcept>

class MyString {
    char* data;
    std::size_t len;

    void allocCopy(const char* s, std::size_t n) {
        data = new char[n + 1];
        std::memcpy(data, s, n + 1);
        len = n;
    }
public:
    // Constructor
    MyString(const char* s = "") {
        allocCopy(s, std::strlen(s));
    }

    // 1. Destructor
    ~MyString() {
        delete[] data;
    }

    // 2. Copy constructor — deep copy
    MyString(const MyString& other) {
        allocCopy(other.data, other.len);
    }

    // 3. Copy assignment — self-assignment guard + release + deep copy
    MyString& operator=(const MyString& other) {
        if (this == &other) return *this;   // self-assignment guard
        delete[] data;                       // release current resource
        allocCopy(other.data, other.len);    // deep copy new resource
        return *this;
    }

    void print() const { std::cout << data << " (len=" << len << ")\n"; }
};

int main() {
    MyString a("hello");
    MyString b = a;         // copy constructor — b gets its own allocation
    b.print();              // hello (len=5)

    MyString c("world");
    c = a;                  // copy assignment — c releases "world", copies "hello"
    c.print();              // hello (len=5)

    a.print();              // hello — a is unaffected
    // All three destructors run cleanly — no double-free
}

Copy-and-Swap Idiom

#include <algorithm>   // std::swap

class MyString {
    char* data;
    std::size_t len;
public:
    MyString(const char* s = "");
    ~MyString() { delete[] data; }

    // Copy constructor (same as before)
    MyString(const MyString& other);

    // Copy-and-swap assignment
    MyString& operator=(MyString other) {  // other is a copy (by value)
        std::swap(data, other.data);       // steal other's resource
        std::swap(len,  other.len);
        return *this;
        // old resource cleaned up by other's destructor
    }
};

By taking other by value, the copy is made once (via the copy constructor), then swapped in. The old resource is released when the temporary other is destroyed at the end of the function. This also handles self-assignment correctly.

Exercise 1

Implement a DynArray class that manages a dynamically allocated array of int. It should store the array pointer and its size. Apply the Rule of Three: write a proper destructor, copy constructor, and copy assignment operator (with self-assignment guard). Test by copying a DynArray, modifying the copy, and verifying the original is unchanged.

Exercise 2

The following class is broken. Identify every memory issue, explain what goes wrong at runtime, and fix it by applying the Rule of Three: 

class Buffer {
    int* buf;
    int  size;
public:
    Buffer(int n) : size(n), buf(new int[n]()) {}
    ~Buffer() { delete[] buf; }
    int& operator[](int i) { return buf[i]; }
};

void test() {
    Buffer a(5);
    a[0] = 10;
    Buffer b(a);     // problem 1
    b[0] = 99;
    Buffer c(3);
    c = a;           // problem 2
}

Exercise 3

Rewrite your DynArray copy assignment operator from Exercise 1 using the copy-and-swap idiom. Add a swap member function (or free function) and implement assignment by taking the parameter by value and swapping. Explain in comments why this version is exception-safe.
