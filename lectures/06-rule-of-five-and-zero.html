Rule of Five & Rule of Zero

move constructor move assignment std::move RAII

Overview

C++11 introduced move semantics: the ability to transfer ownership of a resource from one object to another without copying it. This extends the Rule of Three by two more special member functions, giving us the Rule of Five:

  1. Destructor
  2. Copy constructor
  3. Copy assignment operator
  4. Move constructor (T(T&&))
  5. Move assignment operator (T& operator=(T&&))

The Rule of Zero is the modern alternative: design classes so that they own no raw resources directly — delegate resource management to members that already implement the Rule of Five (std::unique_ptr, std::vector, std::string, …). The compiler-generated special functions then do the right thing automatically.

Notes

Rvalues, Lvalues, and std::move

An lvalue is an expression that refers to a persistent object (has a name, an address). An rvalue is a temporary — it will be discarded after the expression. The && syntax declares an rvalue reference, which can bind to temporaries and allow resources to be stolen rather than copied.

std::move(x) is a cast — it does not move anything by itself. It converts x to an rvalue reference, signalling that the caller permits the resource to be transferred. After std::move, the moved-from object must be left in a valid but unspecified state (typically null/empty).

Move Constructor

Transfers ownership of resources from a temporary (or explicitly moved) object. No allocation — just pointer/handle theft: 

T(T&& other) noexcept
    : data(other.data), len(other.len)   // steal
{
    other.data = nullptr;                // leave in valid state
    other.len  = 0;
}

Mark move operations noexcept whenever possible — the standard library uses this information to choose moves over copies in containers.

Move Assignment Operator

Like move construction, but on an already-constructed object. Must release the existing resource first: 

T& operator=(T&& other) noexcept {
    if (this == &other) return *this;
    delete[] data;           // release current resource
    data = other.data;       // steal
    len  = other.len;
    other.data = nullptr;    // leave in valid state
    other.len  = 0;
    return *this;
}

When the Compiler Generates (or Suppresses) Special Functions

Declaring any of the five special functions suppresses automatic generation of some others:

  • Declaring a destructor suppresses auto-generated move operations (but not copy).
  • Declaring a copy operation suppresses auto-generated move operations.
  • Declaring a move operation suppresses auto-generated copy operations.

Use = default to explicitly request the compiler-generated version, and = delete to explicitly prohibit an operation.

Guideline: if you define any of the five, define or = default / = delete all five so the compiler's behaviour is always intentional.

Rule of Zero

The cleanest solution is to avoid managing raw resources at all. Use RAII wrappers as members: std::unique_ptr for sole ownership, std::shared_ptr for shared ownership, std::vector / std::string for collections and buffers. The compiler-generated copy/move/destructor will call the corresponding operations on those members — which are already correct.

A class following the Rule of Zero has zero special member function definitions.

Code Examples

Full Rule of Five Implementation

#include <iostream>
#include <cstring>
#include <utility>

class Buffer {
    int*        data;
    std::size_t size;
public:
    // Constructor
    explicit Buffer(std::size_t n)
        : data(new int[n]()), size(n) {
        std::cout << "construct\n";
    }

    // 1. Destructor
    ~Buffer() {
        delete[] data;
        std::cout << "destroy\n";
    }

    // 2. Copy constructor
    Buffer(const Buffer& other)
        : data(new int[other.size]), size(other.size) {
        std::memcpy(data, other.data, size * sizeof(int));
        std::cout << "copy construct\n";
    }

    // 3. Copy assignment
    Buffer& operator=(const Buffer& other) {
        if (this == &other) return *this;
        delete[] data;
        data = new int[other.size];
        size = other.size;
        std::memcpy(data, other.data, size * sizeof(int));
        std::cout << "copy assign\n";
        return *this;
    }

    // 4. Move constructor — steal, then null out source
    Buffer(Buffer&& other) noexcept
        : data(other.data), size(other.size) {
        other.data = nullptr;
        other.size = 0;
        std::cout << "move construct\n";
    }

    // 5. Move assignment
    Buffer& operator=(Buffer&& other) noexcept {
        if (this == &other) return *this;
        delete[] data;          // release current
        data = other.data;      // steal
        size = other.size;
        other.data = nullptr;
        other.size = 0;
        std::cout << "move assign\n";
        return *this;
    }

    std::size_t getSize() const { return size; }
    int& operator[](std::size_t i) { return data[i]; }
};

int main() {
    Buffer a(4);                  // construct
    a[0] = 10;

    Buffer b = a;                 // copy construct — b owns its own array
    Buffer c = std::move(a);      // move construct — c steals a's array; a is now empty

    std::cout << "c size: " << c.getSize() << "\n";  // 4
    std::cout << "a size: " << a.getSize() << "\n";  // 0 (moved-from)

    Buffer d(2);
    d = std::move(b);             // move assign
}

Move Enables Efficient Container Operations

#include <vector>
#include <string>
#include <iostream>

class Tag {
    std::string label;
public:
    explicit Tag(std::string s) : label(std::move(s)) {}  // move into member
    const std::string& get() const { return label; }
};

int main() {
    std::vector<Tag> tags;
    tags.reserve(3);

    tags.push_back(Tag("alpha"));           // move-constructs into vector
    tags.emplace_back("beta");              // constructs in-place — no move needed

    std::string s = "gamma";
    tags.push_back(Tag(std::move(s)));      // s transferred, not copied

    for (const auto& t : tags)
        std::cout << t.get() << "\n";
}

Rule of Zero in Practice

#include <memory>
#include <string>
#include <vector>

// No special member functions defined — the compiler generates all five correctly
// because every member already manages its own lifetime.
class Document {
    std::string              title;
    std::vector<std::string> lines;
    std::unique_ptr<int[]>   cache;   // sole ownership, no raw delete needed

public:
    Document(std::string t, int cacheSize)
        : title(std::move(t))
        , cache(std::make_unique<int[]>(cacheSize))
    {}

    void addLine(const std::string& line) { lines.push_back(line); }
    const std::string& getTitle() const   { return title; }
};

int main() {
    Document a("Notes", 64);
    a.addLine("First line");

    Document b = a;              // deep copy: string, vector, and unique_ptr all copy correctly
    Document c = std::move(a);   // move: all resources transferred cheaply
}

Note: std::unique_ptr is move-only, so Document's compiler-generated copy constructor will be = deleted automatically. If you need copyable documents with a cache, replace unique_ptr with vector<int>.

Explicitly Defaulting / Deleting

class NonCopyable {
public:
    NonCopyable() = default;
    ~NonCopyable() = default;

    NonCopyable(const NonCopyable&)            = delete;  // forbid copy
    NonCopyable& operator=(const NonCopyable&) = delete;

    NonCopyable(NonCopyable&&)            = default;      // allow move
    NonCopyable& operator=(NonCopyable&&) = default;
};

class ImmutableValue {
    int val;
public:
    explicit ImmutableValue(int v) : val(v) {}

    ImmutableValue(const ImmutableValue&)            = default;
    ImmutableValue& operator=(const ImmutableValue&) = delete;  // no reassignment
    ImmutableValue(ImmutableValue&&)                 = delete;
    ImmutableValue& operator=(ImmutableValue&&)      = delete;

    int get() const { return val; }
};

    std::string* tracks;
    int          count;
