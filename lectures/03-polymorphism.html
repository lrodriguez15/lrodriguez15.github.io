Polymorphism

oop virtual override abstract dynamic_cast vtable

Overview

The word "polymorphism" means many forms. In C++ it shows up in two completely different mechanisms, and conflating them is the first mistake students make.

Kind When resolved Mechanism Cost
Compile-time (static) At compilation overloading, templates zero
Runtime (dynamic) At execution virtual + vtable + vptr one pointer indirection per call

This lecture is about runtime polymorphism. Compile-time polymorphism (overloading, operator overloading) is covered briefly as contrast; templates are a later topic.

The central promise of runtime polymorphism: write code that operates on a base-class pointer or reference, and the right derived-class function executes automatically — today and for every derived class written tomorrow, without touching the calling code.

Key Ideas

  • Mark a function virtual in the base class once; use override in every derived class every time — the compiler then catches typos that would silently call the wrong function.
  • A class with at least one pure virtual function (= 0) is abstract and cannot be instantiated — it expresses a contract, not an object.
  • A base class meant to be deleted through a base pointer must have a virtual destructor; omitting it is undefined behaviour and a memory leak waiting to happen.
  • dynamic_cast lets you safely recover a derived pointer at runtime, but frequent use is a smell — it means the virtual interface is not doing enough work.

Notes

Compile-Time Polymorphism

The compiler selects the correct function at compile time based on the argument types (for overloading) or the template parameters. No runtime overhead, no vptr, no vtable.

  • Function overloading: same name, different parameter lists.
  • Operator overloading: custom meaning for +, <<, ==, etc. on user-defined types.
  • Templates: generic code parameterised by type — introduced later in the course.

Runtime Polymorphism and virtual

When a base-class function is marked virtual, the compiler builds a vtable (virtual dispatch table) for that class: a static array of function pointers, one slot per virtual function. Every object of a polymorphic class carries a hidden vptr pointing at its class's vtable.

Calling ptr->draw() through a Shape* does three things at runtime:

  • Follow the vptr to the vtable.
  • Read the function pointer in the draw slot.
  • Jump to it.

That is one extra indirection per virtual call — negligible for most code, irrelevant for all teaching code.

Rules for correct use:

  • Declare in the base: virtual void draw() const;
  • Override in the derived: void draw() const override; — the override specifier tells the compiler "this must match a virtual function in a base"; if it doesn't (typo, wrong signature), you get a compile error, not a silent new function.
  • Use final to prevent further overriding: void draw() const final;
  • Give the base class a virtual destructor whenever it is possible that a derived object will be deleted through a base pointer. Without it, only ~Base() runs — the derived destructor is skipped, and any resources the derived class owns leak.

Abstract Classes and Pure Virtual Functions

A pure virtual function is declared with = 0 and has no definition in the base class (though one may be supplied separately if needed). A class with at least one pure virtual function is abstract: the compiler refuses to instantiate it directly.

Abstract classes define a contract — a set of operations every concrete subclass must provide. They are C++'s closest equivalent to interfaces in Java or Go.

The vtable in Practice

Each polymorphic class has exactly one vtable, shared by all its instances. Every instance has exactly one vptr (usually stored at offset 0, making sizeof slightly larger). The vtable is populated at compile/link time; the vptr is set by the constructor.

dynamic_cast

dynamic_cast performs a safe downcast at runtime using RTTI (Run-Time Type Information, enabled by default). For pointer casts it returns nullptr on failure; for reference casts it throws std::bad_cast.

Use it only when you genuinely need to recover the derived type — for example, when a derived class has an operation that has no natural place in the base interface. Frequent dynamic_cast in calling code often signals that the virtual interface is too narrow.

Code Examples

Failure 1 — Missing virtual: Silent Static Dispatch

This is the bug that bites everyone at least once. The code compiles cleanly, runs without a crash, and does the wrong thing.

Broken

// BAD — no virtual keyword
struct Shape {
    void draw() const { std::cout << "Shape::draw\n"; }  // NOT virtual
};

struct Circle : Shape {
    void draw() const { std::cout << "Circle::draw\n"; } // shadows, does not override
};

int main() {
    Circle c;
    Shape* p = &c;
    p->draw();   // prints "Shape::draw" — static dispatch, always calls Shape::draw
}

Adding virtual to Shape::draw and override to Circle::draw is the complete fix. The override keyword then becomes the compile-time proof that dispatch is dynamic.

Failure 2 — Non-Virtual Destructor: Derived Resources Leak

Broken

// BAD — virtual dispatch, but destructor is not virtual
struct Base {
    virtual void speak() const { std::cout << "Base\n"; }
    ~Base() {}            // NOT virtual — deleting through Base* is UB
};

struct Derived : Base {
    int* data;
    Derived() : data(new int[1000]) {}
    ~Derived() { delete[] data; }   // never called when deleted through Base*
    void speak() const override { std::cout << "Derived\n"; }
};

int main() {
    Base* p = new Derived();
    p->speak();   // correct — "Derived" via vtable
    delete p;     // UB: only ~Base() runs; ~Derived() and delete[] data are skipped
}

The fix is one word: virtual ~Base() {} (or = default). This propagates to all derived destructors automatically — no changes to Derived needed.

Run examples/02_nonvirtual_dtor.cpp with -fsanitize=address to watch ASan flag this.

Runtime Polymorphism with virtual and override

#include <iostream>
#include <vector>
#include <memory>

class Shape {
public:
    virtual double area() const = 0;   // pure virtual — Shape is abstract
    virtual void   draw() const = 0;
    virtual ~Shape() = default;        // virtual destructor — always
};

class Circle : public Shape {
    double r;
public:
    explicit Circle(double r) : r(r) {}
    double area() const override { return 3.14159 * r * r; }
    void   draw() const override { std::cout << "Circle, area=" << area() << "\n"; }
};

class Rectangle : public Shape {
    double w, h;
public:
    Rectangle(double w, double h) : w(w), h(h) {}
    double area() const override { return w * h; }
    void   draw() const override { std::cout << "Rectangle, area=" << area() << "\n"; }
};

int main() {
    std::vector<std::unique_ptr<Shape>> shapes;
    shapes.push_back(std::make_unique<Circle>(5.0));
    shapes.push_back(std::make_unique<Rectangle>(4.0, 3.0));
    shapes.push_back(std::make_unique<Circle>(1.5));

    for (const auto& s : shapes)
        s->draw();   // correct override called for each object at runtime
}

Abstract Class as an Interface

#include <iostream>
#include <string>

class Logger {             // pure interface — cannot be instantiated
public:
    virtual void log(const std::string& msg) const = 0;
    virtual ~Logger() = default;
};

class ConsoleLogger : public Logger {
public:
    void log(const std::string& msg) const override {
        std::cout << "[LOG] " << msg << "\n";
    }
};

class FileLogger : public Logger {
    std::string filename;
public:
    explicit FileLogger(const std::string& f) : filename(f) {}
    void log(const std::string& msg) const override {
        // Real code would open the file; simplified for clarity.
        std::cout << "[FILE:" << filename << "] " << msg << "\n";
    }
};

// Caller depends only on Logger — unaware of the concrete type
void doWork(const Logger& logger) {
    logger.log("Starting work");
    logger.log("Work complete");
}

int main() {
    ConsoleLogger cl;
    FileLogger    fl("app.log");
    doWork(cl);   // runtime dispatch to ConsoleLogger
    doWork(fl);   // runtime dispatch to FileLogger
}

dynamic_cast

#include <iostream>
#include <memory>

class Animal {
public:
    virtual void speak() const = 0;
    virtual ~Animal() = default;
};

class Dog : public Animal {
public:
    void speak() const override { std::cout << "Woof!\n"; }
    void fetch() const          { std::cout << "Fetching!\n"; }
};

class Cat : public Animal {
public:
    void speak() const override { std::cout << "Meow!\n"; }
    void purr()  const          { std::cout << "Purring...\n"; }
};

int main() {
    std::unique_ptr<Animal> a = std::make_unique<Dog>();
    a->speak();   // virtual dispatch — prints "Woof!"

    // Safe downcast: confirm the runtime type before using Dog-specific API
    Dog* dog = dynamic_cast<Dog*>(a.get());
    if (dog) {
        dog->fetch();   // safe — confirmed at runtime
    }

    // Failed cast returns nullptr, not a crash
    Cat* cat = dynamic_cast<Cat*>(a.get());
    if (!cat) {
        std::cout << "Not a Cat — cast failed safely\n";
    }
}

Exercises

Exercise 1

Instrument hierarchy. Design an abstract base class Instrument with a pure virtual method play(). Derive at least three concrete instruments (Guitar, Piano, Drums). Store them in a std::vector<std::unique_ptr<Instrument>> and call play() on each element. Verify at runtime that the correct override is invoked for every element.

Exercise 2

Shape totalArea. Extend the Shape hierarchy from the code examples: add a Triangle class. Write a free function double totalArea(const std::vector<Shape*>& shapes) that accumulates and returns the sum of all areas using virtual dispatch. Test it with a mixed collection and print the result.

Exercise 3

Payroll with dynamic_cast. Given the following hierarchy: 

class Employee {
public:
    virtual double salary() const = 0;
    virtual ~Employee() = default;
};
class FullTime : public Employee {
    double base;
public:
    FullTime(double b) : base(b) {}
    double salary() const override { return base; }
};
class PartTime : public Employee {
    double hourly; int hours;
public:
    PartTime(double h, int hrs) : hourly(h), hours(hrs) {}
    double salary() const override { return hourly * hours; }
};

Write a Payroll class that stores a collection of Employee* pointers, computes total payroll using virtual dispatch, and uses dynamic_cast to count how many employees are PartTime. Print both the total payroll and the part-time headcount.
