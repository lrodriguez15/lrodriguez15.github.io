Operator Overloading

operator-overloading friend stream-io functors

Overview

C++ lets you redefine the behaviour of built-in operators (+, ==, <<, …) for user-defined types. Done right, it makes your types feel as natural as int or double. Done wrong, it produces surprising bugs and unreadable code.

Operator family Canonical form Member or free?
Compound assignment (+=, -=, …) returns T& member
Binary arithmetic (+, -, …) takes lhs by value, calls +=, returns T free
Comparison (==, <, …) returns bool free (symmetric conversions)
Stream (<<, >>) returns std::ostream& / std::istream& free (left operand is stream)
Subscript ([]) provide const + non-const overloads member
Call (()) — functor any signature member
Assignment (=) returns T&, guards self-assignment member

Key Ideas

  • Member vs. free: compound-assignment and subscript are members; symmetric binary operators and stream operators are free functions (declare friend for private access).
  • Canonical form: implement += first; define + as a free function that takes lhs by value and calls +=. This avoids duplicating logic and lets copy-elision work.
  • Return types matter: compound-assignment returns T& (to allow chaining); binary arithmetic returns T by value (never a reference — the result is a temporary). Stream operators return std::ostream& / std::istream& to allow chaining (<< a << b).
  • Operator= must guard self-assignment (if (this == &rhs) return *this;) and must return *this — forgetting either is a classic bug.

Notes

General Rules

  • You cannot change operator arity (a binary operator stays binary).
  • You cannot invent new operators or change precedence/associativity.
  • At least one operand must be a user-defined type — you cannot overload int + int.
  • Operators ::, ., .*, ?:, and sizeof cannot be overloaded.
  • Overloading && and || loses short-circuit evaluation — avoid it.

Member vs. Non-Member

An operator overloaded as a member function receives the left-hand operand as the implicit this pointer. An operator overloaded as a non-member (free) function takes both operands explicitly.

  • Use a member for operators that naturally modify the object: +=, -=, [], (), =, prefix/postfix ++/--, and unary -.
  • Use a non-member for symmetric binary operators (+, ==, <) so that implicit conversions apply to both sides equally.
  • Declare the non-member as a friend only when it needs access to private members.

Canonical Forms

Implement += first; define + in terms of it to avoid duplicating logic: 

T& operator+=(const T& rhs);           // member — modifies *this, returns *this
T  operator+(T lhs, const T& rhs) {    // free — lhs is a copy, so we can modify it
    lhs += rhs;
    return lhs;
}

Comparison Operators

Define operator== and operator<; derive the rest in terms of those two: 

friend bool operator!=(const T& a, const T& b) { return !(a == b); }
friend bool operator> (const T& a, const T& b) { return b < a; }
friend bool operator<=(const T& a, const T& b) { return !(b < a); }
friend bool operator>=(const T& a, const T& b) { return !(a < b); }

Stream Operators

operator<< and operator>> must be non-member functions because the left operand is a stream (std::ostream / std::istream), not your type. They return a reference to the stream to allow chaining: 

friend std::ostream& operator<<(std::ostream& os, const T& obj) {
    // write obj to os
    return os;   // <-- must return the stream
}

Assignment Operator — Two Pitfalls

operator= is a member that must:

  • Return T& (not T) — so that a = b = c chains correctly.
  • Return *this.
  • Guard against self-assignment — otherwise you may free a resource and then read from it.

See the failure-first demonstration in Code Examples below.

Code Examples

Full compilable programs are in examples/. The snippets below are the teaching cut.

FAILURE: operator= That Breaks Chaining and Corrupts on Self-Assignment

Broken

// BROKEN — two bugs: returns T (not T&), and no self-assignment guard.
class Buffer {
    char* data;
    size_t size;
public:
    Buffer(size_t n) : data(new char[n]()), size(n) {}
    ~Buffer() { delete[] data; }

    // Bug 1: returns Buffer by value — a = b = c does NOT chain (c is sliced into a copy)
    // Bug 2: no self-assignment guard — a = a frees data then reads garbage
    Buffer operator=(const Buffer& rhs) {      // <-- should be Buffer&
        delete[] data;                          // <-- if rhs is *this, this nukes our own data
        size = rhs.size;
        data = new char[size];
        std::copy(rhs.data, rhs.data + size, data);  // reads freed memory if self-assigning!
        return *this;
    }
};

int main() {
    Buffer a(4), b(4), c(4);
    a = b = c;          // silently wrong: b=c returns a temporary; a=<temp> copies the temp
    Buffer x(4);
    x = x;              // undefined behaviour: deletes x.data, then copies from x.data
}

FIX: Correct operator=

Fixed

// FIXED — returns T&, guards self-assignment
Buffer& operator=(const Buffer& rhs) {
    if (this == &rhs) return *this;    // self-assignment guard
    delete[] data;
    size = rhs.size;
    data = new char[size];
    std::copy(rhs.data, rhs.data + size, data);
    return *this;                      // return reference to *this, enabling chaining
}

Arithmetic & Compound Assignment (Vector2D)

class Vector2D {
public:
    double x, y;
    Vector2D(double x = 0, double y = 0) : x(x), y(y) {}

    // Compound assignment — member
    Vector2D& operator+=(const Vector2D& rhs) {
        x += rhs.x; y += rhs.y;
        return *this;
    }
    Vector2D& operator-=(const Vector2D& rhs) {
        x -= rhs.x; y -= rhs.y;
        return *this;
    }

    // Unary negation — member
    Vector2D operator-() const { return {-x, -y}; }
};

// Binary + built from += — free function (no private access needed)
Vector2D operator+(Vector2D lhs, const Vector2D& rhs) { lhs += rhs; return lhs; }
Vector2D operator-(Vector2D lhs, const Vector2D& rhs) { lhs -= rhs; return lhs; }

Note that lhs is taken by value in the free binary operators — the caller's copy is already made by the pass-by-value; we reuse that copy as our working buffer and return it. Returning Vector2D& here would be wrong (dangling reference to the local lhs).

Comparison Operators (Fraction)

class Fraction {
public:
    int num, den;
    Fraction(int n, int d) : num(n), den(d) {}

    friend bool operator==(const Fraction& a, const Fraction& b) {
        return a.num * b.den == b.num * a.den;
    }
    friend bool operator!=(const Fraction& a, const Fraction& b) { return !(a == b); }
    friend bool operator< (const Fraction& a, const Fraction& b) {
        return a.num * b.den < b.num * a.den;
    }
};

Stream Insertion & Extraction (Point)

class Point {
public:
    double x, y;
    Point(double x = 0, double y = 0) : x(x), y(y) {}

    // Must be non-member: left operand is std::ostream, not Point
    friend std::ostream& operator<<(std::ostream& os, const Point& p) {
        return os << "(" << p.x << ", " << p.y << ")";
    }
    friend std::istream& operator>>(std::istream& is, Point& p) {
        return is >> p.x >> p.y;
    }
};

operator<< takes Point as const& because printing should never modify the object. operator>> takes Point as & (non-const) because reading must modify it.

Subscript Operator (FixedArray)

class FixedArray {
    int data[10];
public:
    FixedArray() { for (auto& v : data) v = 0; }

    // Non-const overload — returns a writable reference
    int& operator[](int i) {
        if (i < 0 || i >= 10) throw std::out_of_range("index out of range");
        return data[i];
    }
    // Const overload — required so the operator works on const FixedArray objects
    const int& operator[](int i) const {
        if (i < 0 || i >= 10) throw std::out_of_range("index out of range");
        return data[i];
    }
};

Always provide both const and non-const overloads for operator[]. Without the const version, code that receives a const FixedArray& cannot even read elements.

Call Operator — Functor (Multiplier)

class Multiplier {
    int factor;
public:
    explicit Multiplier(int f) : factor(f) {}
    int operator()(int x) const { return x * factor; }
};

// Usage
Multiplier triple{3};
std::cout << triple(7);    // 21 — object called like a function

Functors let you pass stateful callable objects to STL algorithms — something plain function pointers cannot do.

Exercises

Exercise 1

Matrix2x2 (canonical form). Implement a Matrix2x2 class (2x2 matrix of double). Overload operator+, operator-, operator* (matrix multiplication), operator==, and operator<<. Use the canonical form: implement compound-assignment members (+=, -=, *=) first, then build the free binary operators on top. Verify with a main() that multiplies two known matrices and checks the result with operator==.

Exercise 2

String wrapper (subscript + const correctness). Create a String class that wraps a std::string and overloads: operator+ (concatenation), operator[] (character access with bounds check via std::out_of_range), operator==, and operator<<. Ensure both the const and non-const overloads of operator[] are present. Write a test that passes a const String to a function and reads a character — confirm it compiles and prints correctly.

Exercise 3

Counter functor (all four increment/decrement variants). Write a Counter functor class with an internal int count. Overload operator() so each call increments the count and returns the new value. Also overload prefix operator++ and operator-- (return T&) and postfix operator++ and operator-- (take a dummy int parameter, return T by value). In main(), demonstrate that prefix ++c returns the already-incremented value and postfix c++ returns the value before incrementing.
