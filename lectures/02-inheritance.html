Inheritance

inheritance access specifiers protected virtual

Overview

Inheritance is a mechanism that lets a new class (the derived class) acquire the members of an existing class (the base class), enabling code reuse and the foundation of polymorphism. In C++ inheritance is declared with a colon and an access specifier.

Key concepts covered in this lecture:

  • Syntax for single inheritance
  • Public, protected, and private inheritance and what each exposes
  • How constructors and destructors chain through a hierarchy
  • The role of protected members
  • Declaring virtual functions as a bridge to polymorphism

Notes

Syntax

The general form of a derived class declaration is:

class Derived : <access-specifier> Base {
    // additional members
};

The access specifier controls which inherited members are visible outside the derived class. Most real-world hierarchies use public inheritance.

Access Specifiers in Inheritance

The access specifier on the inheritance declaration adjusts the maximum visibility of inherited members:

  • public — public members of Base stay public; protected stays protected
  • protected — both public and protected members of Base become protected in Derived
  • private — all inherited members become private in Derived (implementation inheritance)

Rule of thumb: use public when modelling an is-a relationship (a Dog is-a Animal). Private/protected inheritance models implemented-in-terms-of and is rarely needed.

Constructor & Destructor Chaining

When a derived object is created, the base constructor runs first, then the derived constructor. Destruction is the reverse: derived destructor first, then base. You select which base constructor to call in the derived class's member initialiser list.

The protected Access Level

Members declared protected are inaccessible to external code (like private) but are accessible in derived classes. Use protected sparingly — it tightly couples the base and derived implementations.

Introducing virtual

Marking a base-class member function virtual tells the compiler to dispatch calls through the object's actual runtime type rather than its declared type. This is the entry point to polymorphism (covered in Lecture 03). Always declare the base destructor virtual when the class is intended to be subclassed.

Code Examples

Single Inheritance & Access Specifiers

#include <iostream>
#include <string>

class Animal {
public:
    std::string name;

    Animal(const std::string& n) : name(n) {}

    void breathe() const {
        std::cout << name << " is breathing\n";
    }
};

class Dog : public Animal {  // public inheritance — is-a Animal
public:
    Dog(const std::string& n) : Animal(n) {}  // delegate to base ctor

    void bark() const {
        std::cout << name << " says: Woof!\n";  // 'name' is inherited
    }
};

int main() {
    Dog d("Rex");
    d.breathe();  // inherited from Animal
    d.bark();     // defined in Dog
}

Constructor Chaining

#include <iostream>

class Shape {
protected:
    double x, y;  // position — accessible in derived classes
public:
    Shape(double x, double y) : x(x), y(y) {
        std::cout << "Shape constructed at (" << x << ", " << y << ")\n";
    }
    virtual ~Shape() {   // virtual destructor — essential for polymorphism
        std::cout << "Shape destroyed\n";
    }
};

class Circle : public Shape {
    double radius;
public:
    Circle(double x, double y, double r)
        : Shape(x, y), radius(r) {    // base constructor in initialiser list
        std::cout << "Circle constructed, radius=" << radius << "\n";
    }
    ~Circle() override {
        std::cout << "Circle destroyed\n";
    }
    double area() const { return 3.14159 * radius * radius; }
};

int main() {
    Circle c(0, 0, 5);
    std::cout << "Area: " << c.area() << "\n";
    // Destructors fire in reverse order: Circle then Shape
}

Using protected Members

#include <iostream>

class BankAccount {
protected:
    double balance;  // derived classes can read/write, outside code cannot
public:
    BankAccount(double initial) : balance(initial) {}
    double getBalance() const { return balance; }
};

class SavingsAccount : public BankAccount {
    double interestRate;
public:
    SavingsAccount(double initial, double rate)
        : BankAccount(initial), interestRate(rate) {}

    void applyInterest() {
        balance *= (1.0 + interestRate);  // direct access to protected member
    }
};

int main() {
    SavingsAccount sa(1000.0, 0.05);
    sa.applyInterest();
    std::cout << "Balance: " << sa.getBalance() << "\n"; // 1050
    // sa.balance = 0;  // ERROR: protected — not accessible outside the hierarchy
}

Virtual Functions Preview

#include <iostream>

class Animal {
public:
    virtual void speak() const {      // virtual — runtime dispatch
        std::cout << "...\n";
    }
    virtual ~Animal() = default;
};

class Cat : public Animal {
public:
    void speak() const override {     // override keyword — compile-time safety check
        std::cout << "Meow!\n";
    }
};

int main() {
    Animal* a = new Cat();
    a->speak();   // prints "Meow!" — dispatched to Cat::speak at runtime
    delete a;     // safe because ~Animal is virtual
}

Exercises

Exercise 1

Create a class Vehicle with protected members brand (string) and speed (double). Derive Car and Motorcycle from it. Each subclass should have an additional attribute (e.g., number of doors for Car, handlebar type for Motorcycle) and a method to display full vehicle info. Use proper constructor chaining.

Exercise 2

Implement a three-level hierarchy: LivingThing → Animal → Mammal. Each class should add one attribute and call the base constructor in its initialiser list. In main, create a Mammal object and verify that all attributes are correctly initialised by printing them. Trace the constructor and destructor call order with std::cout statements.

Exercise 3

Explain what happens in the following code and identify the bug. Then fix it: 

class Base {
public:
    ~Base() { std::cout << "Base destructor\n"; }
    virtual void greet() { std::cout << "Hello from Base\n"; }
};

class Derived : public Base {
public:
    ~Derived() { std::cout << "Derived destructor\n"; }
    void greet() override { std::cout << "Hello from Derived\n"; }
};

int main() {
    Base* obj = new Derived();
    obj->greet();
    delete obj;   // What is the problem here?
}
