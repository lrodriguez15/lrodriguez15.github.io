Smart Pointers

unique_ptr shared_ptr weak_ptr RAII

Overview

A smart pointer is a class that wraps a raw pointer and manages the lifetime of the pointed-to object automatically. When the smart pointer goes out of scope, it deletes the object — no manual delete required. This is RAII applied to heap memory.

C++14 provides three smart pointer types in <memory>:

  • unique_ptr — sole, non-shared ownership. Move-only.
  • shared_ptr — shared ownership via reference counting.
  • weak_ptr — non-owning observer of a shared_ptr resource; breaks reference cycles.

Default rule: reach for unique_ptr first. Upgrade to shared_ptr only when you genuinely need shared ownership. Use raw pointers only as non-owning observers.

Notes

unique_ptr — Sole Ownership

  • One and only one unique_ptr can own an object at any time.
  • Cannot be copied; can be moved with std::move.
  • Destroyed when it goes out of scope or is explicitly reset.
  • Zero overhead over a raw pointer in release builds.
  • Create with std::make_unique<T>(args…) (C++14).

shared_ptr — Shared Ownership

  • Multiple shared_ptr instances can own the same object.
  • An internal reference count tracks how many owners exist.
  • The object is destroyed when the last shared_ptr owning it is destroyed or reset.
  • Create with std::make_shared<T>(args…) — preferred: single allocation for object + control block.
  • Slight overhead: atomic ref-count increment/decrement on copy/destroy.

weak_ptr — Non-Owning Observer

  • Does not contribute to the reference count.
  • Must be converted to a shared_ptr (via .lock()) before the resource can be accessed.
  • .lock() returns an empty shared_ptr if the resource has already been destroyed.
  • Primary use: breaking reference cycles that would otherwise prevent objects from ever being freed.

Ownership vs Observation

Use raw pointers and raw references freely as non-owning handles — there is no need to wrap everything in a smart pointer. The rule is about ownership, not about access:

  • Function parameter that just uses an object → const T& or T*
  • Function that takes ownership → unique_ptr<T> by value
  • Function that shares ownership → shared_ptr<T>

Code Examples

unique_ptr Basics

#include <memory>
#include <iostream>

class Engine {
public:
    Engine()  { std::cout << "Engine ON\n";  }
    ~Engine() { std::cout << "Engine OFF\n"; }
    void run() const { std::cout << "vroom\n"; }
};

int main() {
    // Prefer make_unique over 'new'
    auto eng = std::make_unique<Engine>();
    eng->run();

    // Transfer ownership — eng is now empty
    auto eng2 = std::move(eng);
    if (!eng) std::cout << "eng is empty\n";
    eng2->run();

    // eng2 goes out of scope here → ~Engine() called automatically
}

unique_ptr in a Class (Rule of Zero)

#include <memory>
#include <string>
#include <iostream>

class Car {
    std::string              brand;
    std::unique_ptr<Engine> engine;   // Car owns its Engine
public:
    Car(const std::string& b)
        : brand(b), engine(std::make_unique<Engine>()) {}

    void drive() const { engine->run(); }

    // No destructor needed — unique_ptr destroys Engine automatically.
    // Move is auto-generated. Copy is deleted (unique_ptr is move-only).
};

int main() {
    Car c("Toyota");
    c.drive();

    Car c2 = std::move(c);   // ownership of Engine transfers to c2
    c2.drive();
}

shared_ptr and Reference Counting

#include <memory>
#include <iostream>

struct Node {
    int value;
    Node(int v) : value(v) { std::cout << "Node(" << v << ") created\n"; }
    ~Node()                 { std::cout << "Node(" << value << ") destroyed\n"; }
};

int main() {
    std::shared_ptr<Node> a = std::make_shared<Node>(42);
    std::cout << "use_count: " << a.use_count() << "\n";  // 1

    {
        std::shared_ptr<Node> b = a;   // both own the same Node
        std::cout << "use_count: " << a.use_count() << "\n";  // 2

        std::shared_ptr<Node> c = a;
        std::cout << "use_count: " << a.use_count() << "\n";  // 3
    } // b and c destroyed — count drops to 1

    std::cout << "use_count: " << a.use_count() << "\n";  // 1
} // a destroyed — count hits 0 → Node(42) destroyed

weak_ptr Breaking a Reference Cycle

#include <memory>
#include <iostream>

struct B;  // forward declaration

struct A {
    std::shared_ptr<B> b_ptr;
    ~A() { std::cout << "~A\n"; }
};

struct B {
    std::weak_ptr<A> a_ptr;   // weak — does NOT keep A alive
    ~B() { std::cout << "~B\n"; }
};

int main() {
    auto a = std::make_shared<A>();
    auto b = std::make_shared<B>();

    a->b_ptr = b;          // A owns B
    b->a_ptr = a;          // B observes A (weak — no cycle)

    // If b_ptr were shared_ptr: a and b would form a cycle and never be freed.
    // With weak_ptr: when main exits, a's count → 0 → ~A → b's count → 0 → ~B
}

Accessing Through weak_ptr

#include <memory>
#include <iostream>

int main() {
    std::shared_ptr<int> sp = std::make_shared<int>(100);
    std::weak_ptr<int>   wp = sp;

    // Must lock before use
    if (auto locked = wp.lock()) {
        std::cout << "value: " << *locked << "\n";  // 100
    }

    sp.reset();   // destroy the object

    if (wp.lock() == nullptr) {
        std::cout << "resource is gone\n";
    }
}

Exercises

Exercise 1

Implement a Zoo class that owns a collection of Animal objects (use the polymorphic hierarchy from Lecture 03). Store them as std::vector<std::unique_ptr<Animal>>. Add an addAnimal method that takes a unique_ptr by value. Implement a makeNoise() that calls speak() on every animal via virtual dispatch. Verify that all animals are destroyed automatically when the Zoo goes out of scope.

Exercise 2

Create a shared Config object (key-value store implemented as std::unordered_map<std::string, std::string>). Two classes, Server and Logger, should each hold a shared_ptr<Config>. Demonstrate that modifying the config through one class is visible through the other, and that the config is destroyed only after both classes are destroyed.

Exercise 3

Build a doubly-linked list node structure where each node holds a shared_ptr to the next node and a weak_ptr to the previous node. Insert five integer nodes, then traverse forward and backward. Verify (with destructor messages) that all nodes are freed correctly when the head pointer is reset.
