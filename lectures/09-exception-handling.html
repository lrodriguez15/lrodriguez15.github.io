Exception Handling

try / catch throw std::exception noexcept exception-safety stack-unwinding

Overview

Exception handling separates error-detection code from error-recovery code. Instead of checking return codes at every call site, a function throws an exception object when something goes wrong; the runtime unwinds the call stack until a matching catch block handles it.

Safety guarantee What it promises Typical implementation
No-throw (noexcept) The operation never throws. std::terminate if it does. Moves, swaps, destructors
Strong If an operation throws, program state is unchanged — commit-or-rollback. Copy-and-swap idiom
Basic If an operation throws, no resources leak and objects remain in a valid (but possibly changed) state. Smart pointers + invariant check
None No promise — leaks and corrupt state are possible. Raw new/delete without RAII

Key Ideas

  • throw exits the current scope immediately; the runtime walks back up the call stack looking for a matching catch.
  • Always catch by const reference (catch (const std::exception& e)) to avoid slicing and unnecessary copies.
  • Stack unwinding destroys all local objects in reverse-construction order — RAII turns this into automatic resource cleanup.
  • noexcept is a contract: the compiler may generate better code, and the standard library uses it to prefer moves over copies in containers.
  • The leak-on-throw failure is the core motivator for RAII: a delete after a throw is dead code.

Notes

try / throw / catch

Code that might fail goes inside a try block. If a problem is detected, a throw expression creates an exception object and immediately exits the current scope. The runtime searches up the call stack for a catch block whose type matches the thrown object.

  • Throw any copyable type — by convention, throw objects of types derived from std::exception.
  • Catch by const reference: catch (const std::exception& e) — avoids slicing and unnecessary copies.
  • catch (...) catches everything — use as a last resort or in main.
  • Re-throw with a bare throw; inside a catch block — preserves the original exception type.

Standard Exception Hierarchy

All standard exceptions inherit from std::exception (in <stdexcept>):

  • std::logic_error — bugs detectable before runtime (invalid_argument, out_of_range, length_error)
  • std::runtime_error — problems only detectable at runtime (overflow_error, underflow_error)
  • std::bad_alloc — thrown by new when memory is exhausted
  • std::bad_cast — thrown by a failing reference dynamic_cast

Every standard exception exposes .what() returning a const char* description.

Catch order matters: list more-derived types before less-derived ones, or a base-class handler will swallow every subtype.

Custom Exception Classes

Derive from std::runtime_error or std::logic_error to create domain-specific exceptions that carry extra context and can be caught specifically or generically. Override what() only when you need a dynamically built message; otherwise pass the message string to the base-class constructor.

Stack Unwinding and RAII — The Leak Demo

This is the failure that motivates everything:

// BAD: raw new/delete — the delete is dead code if the throw fires first
void riskyRaw() {
    int* p = new int[1000];   // acquired
    mayThrow();               // if this throws, the line below never runs
    delete[] p;               // LEAKED
}

When mayThrow() throws, C++ immediately starts unwinding. The delete[] p line is never reached. The allocation leaks. AddressSanitizer will confirm it.

The fix is to wrap p in a std::unique_ptr — its destructor runs automatically during unwinding: 

// GOOD: unique_ptr destructor fires during unwinding — no leak
void riskyRAII() {
    auto p = std::make_unique<int[]>(1000);
    mayThrow();               // if this throws…
    // …~unique_ptr() runs here automatically. Memory freed.
}

No extra cleanup code. No try/catch required. The destructor is the cleanup.

noexcept

Marking a function noexcept promises it will never throw. The compiler may generate better code; the standard library uses this to prefer moves over copies in containers. If a noexcept function does throw, std::terminate() is called immediately — no handler gets a chance.

  • Always mark move constructors and move assignment operators noexcept when possible.
  • Mark swap and destructors noexcept — the strong guarantee often depends on it.
  • noexcept(expr) is the conditional form: noexcept(noexcept(T::swap(...))) propagates the guarantee from a dependent operation.

Exception Safety Guarantees

Providing a guarantee is a design decision, not an accident. Aim for the strong guarantee for mutating operations on important state. The copy-and-swap idiom achieves it:

  1. Make a copy of the object being modified.
  2. Perform all potentially-throwing work on the copy.
  3. Swap the copy into place — swap must be noexcept.

If any step before the swap throws, the original is untouched. After the swap succeeds, the old state is destroyed in the copy's destructor — which also must not throw.

Code Examples

Basic try / catch / throw

#include <iostream>
#include <stdexcept>

double divide(double a, double b) {
    if (b == 0.0)
        throw std::invalid_argument("Division by zero");
    return a / b;
}

int main() {
    try {
        std::cout << divide(10, 2) << "\n";   // 5
        std::cout << divide(10, 0) << "\n";   // throws
    }
    catch (const std::invalid_argument& e) {
        std::cerr << "Caught: " << e.what() << "\n";
    }
    std::cout << "Program continues\n";
}

Catching Multiple Exception Types

#include <vector>
#include <stdexcept>
#include <iostream>

int safeAt(const std::vector<int>& v, int i) {
    if (i < 0)
        throw std::invalid_argument("Negative index");
    return v.at(i);   // throws std::out_of_range if i >= v.size()
}

int main() {
    std::vector<int> data = {10, 20, 30};

    for (int idx : {1, -1, 99}) {
        try {
            std::cout << "data[" << idx << "] = " << safeAt(data, idx) << "\n";
        }
        catch (const std::invalid_argument& e) {
            std::cerr << "Bad argument: " << e.what() << "\n";
        }
        catch (const std::out_of_range& e) {
            std::cerr << "Out of range: " << e.what() << "\n";
        }
    }
}

Custom Exception Classes

#include <stdexcept>
#include <string>
#include <iostream>

class InsufficientFundsError : public std::runtime_error {
    double available;
    double requested;
public:
    InsufficientFundsError(double avail, double req)
        : std::runtime_error("Insufficient funds")
        , available(avail), requested(req) {}

    double getAvailable() const { return available; }
    double getRequested() const { return requested; }
};

class BankAccount {
    double balance;
public:
    explicit BankAccount(double initial) : balance(initial) {}

    void withdraw(double amount) {
        if (amount > balance)
            throw InsufficientFundsError(balance, amount);
        balance -= amount;
    }
    double getBalance() const { return balance; }
};

int main() {
    BankAccount acc(100.0);
    try {
        acc.withdraw(40.0);
        std::cout << "Balance: " << acc.getBalance() << "\n";  // 60
        acc.withdraw(80.0);   // throws
    }
    catch (const InsufficientFundsError& e) {
        std::cerr << e.what()
                  << " — have: " << e.getAvailable()
                  << ", need: "  << e.getRequested() << "\n";
    }
}

Failure First — Raw new/delete Leaks on Throw

Broken

// BAD — run with -fsanitize=address to watch the leak
#include <iostream>
#include <stdexcept>

void mayThrow() {
    throw std::runtime_error("something went wrong");
}

void riskyRaw() {
    int* buf = new int[1000];    // acquired
    std::cout << "Buffer acquired at " << buf << "\n";
    mayThrow();                  // throws — the delete below is dead code
    delete[] buf;                // NEVER REACHED
}

int main() {
    try { riskyRaw(); }
    catch (const std::exception& e) {
        std::cerr << "Caught: " << e.what() << "\n";
    }
    // buf is leaked — AddressSanitizer will report it
}

Fix — RAII Cleans Up During Stack Unwinding

Fixed

// GOOD — unique_ptr destructor fires automatically; no leak
#include <iostream>
#include <memory>
#include <stdexcept>

void mayThrow() {
    throw std::runtime_error("something went wrong");
}

void riskyRAII() {
    auto buf = std::make_unique<int[]>(1000);
    std::cout << "Buffer acquired\n";
    mayThrow();
    // ~unique_ptr<int[]> runs here during unwinding — memory freed
}

int main() {
    try { riskyRAII(); }
    catch (const std::exception& e) {
        std::cerr << "Caught: " << e.what() << "\n";
    }
    std::cout << "Clean exit — no leak\n";
}

Stack Unwinding with Multiple Resources

#include <memory>
#include <iostream>
#include <stdexcept>

struct Resource {
    std::string name;
    Resource(const std::string& n) : name(n) { std::cout << "Acquired " << name << "\n"; }
    ~Resource()                               { std::cout << "Released " << name << "\n"; }
};

void riskyOperation() {
    auto r1 = std::make_unique<Resource>("DB connection");
    auto r2 = std::make_unique<Resource>("File handle");

    throw std::runtime_error("Something went wrong");

    // r1 and r2 are never "manually" deleted,
    // but their destructors run during stack unwinding — no leak.
}

int main() {
    try {
        riskyOperation();
    }
    catch (const std::runtime_error& e) {
        std::cerr << "Error: " << e.what() << "\n";
    }
    std::cout << "Clean exit\n";
}

noexcept and Re-throw

#include <iostream>
#include <stdexcept>

// Unconditionally does not throw — std::terminate() if it does
void swapInts(int& a, int& b) noexcept {
    int tmp = a; a = b; b = tmp;
}

void processFile(const std::string& path) {
    try {
        if (path.empty())
            throw std::invalid_argument("Empty path");
        // ... open and process file
    }
    catch (const std::exception& e) {
        std::cerr << "[processFile] caught: " << e.what() << "\n";
        throw;   // re-throw to caller — bare 'throw' preserves type
    }
}

int main() {
    try {
        processFile("");
    }
    catch (const std::invalid_argument& e) {
        std::cerr << "[main] handled: " << e.what() << "\n";
    }
}

Safe Stack. Implement a Stack<T> class backed by a std::vector with: push(), pop(), top(), and isEmpty(). pop() and top() should throw std::underflow_error on an empty stack. Write a test in main that catches this exception and prints a helpful message without crashing.

Exercise 2

Registration Exceptions. Create a hierarchy of custom exceptions for a university registration system: RegistrationError (base, derives from std::runtime_error) with two derived types: CourseFull and PrerequisiteNotMet. Each should carry relevant data (e.g., course name, maximum capacity, or the missing prerequisite name). Write an enroll() function that throws the appropriate exception, and a main that catches them both specifically and prints a different message for each.

Exercise 3

Leak vs. Safe (demonstrate with AddressSanitizer). Write two versions of a function that acquires two resources with new and then throws:

(a) Using raw new/delete — add destructor print statements and show where the leak occurs. Build with -fsanitize=address and confirm ASan reports the leak.

(b) Using std::unique_ptr — show that both resources are cleaned up automatically even when the throw fires. Confirm ASan reports nothing.

Explain in a comment why (a) leaks but (b) does not.
