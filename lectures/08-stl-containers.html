STL Containers & Algorithms

vector map set iterators algorithms stl

Overview

The Standard Template Library hands you a toolbox of production-quality, type-safe containers and algorithms. The choice of container is not cosmetic — pick the wrong one and you pay O(n) where you should pay O(1), or you silently corrupt memory when an iterator you're holding gets invalidated. This lecture teaches you how to choose, how to use, and — critically — where the traps are.

Container Internal structure Access Insert (end) Insert (middle) Search Ordered
std::vector<T> contiguous array O(1) amortised O(1) O(n) O(n) insertion order
std::array<T,N> stack array O(1) — (fixed) — (fixed) O(n) fixed
std::list<T> doubly-linked list O(n) O(1) O(1) given iterator O(n) insertion order
std::map<K,V> red-black tree O(log n) O(log n) O(log n) O(log n) sorted by key
std::unordered_map<K,V> hash table O(1) avg O(1) avg O(1) avg O(1) avg none
std::set<T> red-black tree O(log n) O(log n) O(log n) O(log n) sorted

Default rule: reach for std::vector first. Switch to another container only when you have a concrete complexity or ownership reason.

Key Ideas

  • Every STL container manages its own memory and exposes an iterator interface that algorithms work against uniformly.
  • Iterator invalidation is the most common STL bug: certain operations (e.g. push_back, erase) destroy existing iterators. Using a dead iterator is undefined behaviour.
  • std::map gives O(log n) sorted access; std::unordered_map gives O(1) average unsorted access. Know which you need before you type the name.
  • Prefer algorithms (std::sort, std::find_if, std::count_if) over hand-written loops: they are harder to get wrong and their intent is self-documenting.

Notes

std::vector — The Default Container

A contiguous, dynamically-resizable array. Elements sit next to each other in memory — excellent cache behaviour. Random access is O(1); push_back is amortised O(1); insertion or removal in the middle is O(n) because every subsequent element shifts.

Key operations:

  • push_back(v) / emplace_back(args…) — add to end (prefer emplace_back to avoid an extra copy)
  • pop_back() — remove last element in O(1)
  • reserve(n) — pre-allocate capacity; avoids repeated reallocations in a known-size loop
  • operator[] — unchecked access (no exception on out-of-bounds); .at(i) — bounds-checked
  • begin() / end() — iterator range used by all standard algorithms
  • erase(it) — removes the element at it, returns the iterator to the next element

When not to use vector: if you need O(1) insertion/removal in the middle and you already hold an iterator to that position, consider std::list. If you need O(1) lookup by key, use std::unordered_map.

std::array — Fixed-Size Stack Array

Wraps a C-style array with the full STL interface. Size is a compile-time constant — no heap allocation at all. Prefer over raw C arrays (int a[4]) whenever the size is known at compile time: you get .size(), .at(), iterators, and copy semantics for free.

std::list — Doubly-Linked List

O(1) insertion and removal at any position given an iterator to that position. Pays for it with O(n) random access and poor cache locality. Use when:

  • you frequently insert or delete in the middle of the sequence, and
  • you hold iterators to nodes that must remain valid after those operations.

std::list::erase(it) does not invalidate any other iterators (unlike vector).

std::map & std::unordered_map

Both map keys to values; they differ in ordering guarantees and complexity:

  • std::map<K,V> — red-black tree; keys always sorted; O(log n) for every operation.
  • std::unordered_map<K,V> — hash table; no ordering; O(1) average for lookup/insert (worst case O(n) under hash collision).

Both expose the same interface:

  • operator[] — inserts a default-constructed value if the key is absent. Avoid when you only want to read — use .find() or .at() instead.
  • .at(key) — throws std::out_of_range if absent; safe read.
  • .find(key) — returns end() if absent; fastest explicit check.
  • .count(key) — returns 0 or 1 (use to test existence without inserting).

Iterators

An iterator is an object that behaves like a pointer into a container. All STL containers expose begin() (first element) and end() (one-past-last). The range-based for loop is syntactic sugar for iterator traversal: 

// These two are equivalent:
for (int n : nums) { /* … */ }

for (auto it = nums.begin(); it != nums.end(); ++it) {
    int n = *it;
    /* … */
}

Use cbegin() / cend() when you only need read access (communicates intent, prevents accidental mutation).

Iterator Invalidation — The Trap

Certain operations invalidate all existing iterators into a container. Using an invalidated iterator is undefined behaviour — it may crash, silently corrupt data, or appear to work and fail only in production.

Operation Containers affected Iterators invalidated
push_back / emplace_back (triggers reallocation) vector all
insert / erase at a position vector that position and all after it
erase a node list, map, unordered_map only the erased iterator
rehash / heavy insert unordered_map all

The most common mistake: erasing elements from a vector inside a range-based for, or storing an iterator before a push_back and using it after.

The Erase-Remove Idiom

To remove all elements satisfying a predicate from a vector:

// WRONG — UB: erasing invalidates the iterator the range-for holds
for (auto it = v.begin(); it != v.end(); ++it) {
    if (*it % 2 == 0) v.erase(it);   // it is now invalid
}

// CORRECT — erase-remove idiom
#include <algorithm>
v.erase(std::remove_if(v.begin(), v.end(),
    [](int x) { return x % 2 == 0; }), v.end());

std::remove_if shuffles matching elements to the end and returns an iterator to the new logical end. vector::erase then chops off that tail — one allocation-free pass.

Alternatively, use the iterator-returning form of erase:

for (auto it = v.begin(); it != v.end(); ) {
    if (*it % 2 == 0)
        it = v.erase(it);   // erase returns next valid iterator
    else
        ++it;
}

Choosing the Right Container — The Cost of Getting It Wrong

Wrong-container bugs are performance bugs that look like correct code:

// O(n) lookup — fine for 10 elements, unusable for 10 000
std::vector<std::pair<std::string, int>> scores;
auto it = std::find_if(scores.begin(), scores.end(),
    [](const auto& p){ return p.first == "Alice"; });

// O(1) lookup — use this when you lookup by key
std::unordered_map<std::string, int> scores;
auto it = scores.find("Alice");   // hash lookup, O(1) average

Rule of thumb: if you are repeatedly looking up by a key, you want a map, not a vector.

Common Algorithms (<algorithm>)

All algorithms operate on iterator ranges [begin, end) and work with any container that provides the right iterator category.

  • std::sort(begin, end, cmp) — sort in-place (requires random-access iterators: vector, array)
  • std::find(begin, end, val) — first element equal to val; returns end() if not found
  • std::find_if(begin, end, pred) — first element satisfying predicate
  • std::count_if(begin, end, pred) — count elements satisfying predicate
  • std::for_each(begin, end, fn) — call fn on each element (side-effect focused)
  • std::transform(in_b, in_e, out_b, fn) — map a function over a range into an output range
  • std::remove_if(begin, end, pred) — shuffle matching elements to the end (pair with erase)
  • std::copy_if(in_b, in_e, out_b, pred) — copy matching elements to output range
  • std::unique(begin, end) — collapse consecutive duplicates (sort first for full dedup)
  • std::accumulate(begin, end, init) — fold/reduce; lives in <numeric>

Code Examples

std::vector — Core Operations

#include <vector>
#include <iostream>

int main() {
    std::vector<int> nums;
    nums.reserve(5);           // pre-allocate — avoids repeated reallocations

    for (int i = 1; i <= 5; ++i)
        nums.push_back(i * 10);

    // Range-based for
    for (int n : nums)
        std::cout << n << " ";   // 10 20 30 40 50
    std::cout << "\n";

    nums.erase(nums.begin() + 2);  // remove element at index 2 (value 30)

    std::cout << "size: " << nums.size() << "\n";  // 4
    std::cout << "at(1): " << nums.at(1) << "\n";  // 20 (bounds-checked)
}

vector of Polymorphic Objects

#include <vector>
#include <memory>
#include <iostream>

class Shape {
public:
    virtual void draw() const = 0;
    virtual ~Shape() = default;
};
class Circle    : public Shape { public: void draw() const override { std::cout << "Circle\n";    } };
class Rectangle : public Shape { public: void draw() const override { std::cout << "Rectangle\n"; } };
class Triangle  : public Shape { public: void draw() const override { std::cout << "Triangle\n";  } };

int main() {
    std::vector<std::unique_ptr<Shape>> scene;
    scene.push_back(std::make_unique<Circle>());
    scene.push_back(std::make_unique<Rectangle>());
    scene.push_back(std::make_unique<Triangle>());

    for (const auto& s : scene)
        s->draw();   // runtime dispatch per element
}

Failure → Fix: Iterator Invalidation in a Loop

Broken

// WRONG — undefined behaviour: erasing inside a range-for on vector
std::vector<int> v = {1, 2, 3, 4, 5};
for (int n : v) {
    if (n % 2 == 0)
        v.erase(std::find(v.begin(), v.end(), n));  // UB: range-for iterator invalidated
}

Fixed

// FIX 1 — erase-remove idiom (preferred)
std::vector<int> v = {1, 2, 3, 4, 5};
v.erase(std::remove_if(v.begin(), v.end(),
    [](int x){ return x % 2 == 0; }), v.end());
// v is now {1, 3, 5}

// FIX 2 — manual iterator loop using the return value of erase()
for (auto it = v.begin(); it != v.end(); ) {
    if (*it % 2 == 0)
        it = v.erase(it);   // erase() returns the next valid iterator
    else
        ++it;
}

Failure → Fix: Wrong Container for Key Lookup

Broken

// WRONG — O(n) linear scan per lookup; unusable at scale
std::vector<std::pair<std::string, int>> scores = {
    {"Alice", 95}, {"Bob", 82}, {"Carol", 88}
};
// Finding "Carol" scans every element
auto it = std::find_if(scores.begin(), scores.end(),
    [](const auto& p){ return p.first == "Carol"; });

Fixed

// FIX — O(1) average with unordered_map
std::unordered_map<std::string, int> scores = {
    {"Alice", 95}, {"Bob", 82}, {"Carol", 88}
};
auto it = scores.find("Carol");   // hash lookup
if (it != scores.end())
    std::cout << it->second << "\n";  // 88

std::array — Fixed-Size

#include <array>
#include <numeric>   // std::accumulate
#include <iostream>

int main() {
    std::array<double, 4> temps = {36.5, 37.1, 36.8, 38.0};

    double avg = std::accumulate(temps.begin(), temps.end(), 0.0) / temps.size();
    std::cout << "Average temp: " << avg << "\n";

    for (std::size_t i = 0; i < temps.size(); ++i)
        std::cout << "Day " << i + 1 << ": " << temps[i] << "\n";
}

std::map — Key-Value Store

#include <map>
#include <string>
#include <iostream>

int main() {
    std::map<std::string, int> grades;
    grades["Alice"] = 95;
    grades["Bob"]   = 82;
    grades["Carol"] = 88;

    // Iterate in alphabetical key order
    for (const auto& pair : grades)
        std::cout << pair.first << ": " << pair.second << "\n";

    // Safe lookup — .find() does NOT insert a default value
    auto it = grades.find("Bob");
    if (it != grades.end())
        std::cout << "Bob's grade: " << it->second << "\n";

    // Existence check without insertion
    std::cout << grades.count("Dave") << "\n";  // 0 — not found
}

Algorithms: sort, find_if, count_if

#include <vector>
#include <algorithm>
#include <iostream>
#include <string>

struct Student {
    std::string name;
    int         grade;
};

int main() {
    std::vector<Student> students = {
        {"Alice", 95}, {"Bob", 72}, {"Carol", 88}, {"Dave", 60}, {"Eve", 91}
    };

    // Sort by grade descending
    std::sort(students.begin(), students.end(),
        [](const Student& a, const Student& b) { return a.grade > b.grade; });

    // Count students who passed (grade >= 70)
    int passed = std::count_if(students.begin(), students.end(),
        [](const Student& s) { return s.grade >= 70; });
    std::cout << "Passed: " << passed << "\n";  // 4

    // Find first student with grade < 70
    auto it = std::find_if(students.begin(), students.end(),
        [](const Student& s) { return s.grade < 70; });
    if (it != students.end())
        std::cout << "At risk: " << it->name << "\n";

    // Print sorted ranking
    for (const auto& s : students)
        std::cout << s.name << " - " << s.grade << "\n";
}

Exercises

Exercise 1

Vector pipeline. Read a sequence of integers from the user until 0 is entered. Store them in a std::vector. Then:

  • (a) print the sorted sequence;
  • (b) print the sum and average using std::accumulate;
  • (c) copy only the even numbers into a second vector using std::copy_if;
  • (d) remove all duplicates using the sort + std::unique + erase pattern.

Discuss: why does std::unique require a sorted range first?

Exercise 2

Word frequency counter. Build a word-frequency counter using std::unordered_map<std::string, int>. Read words from a hardcoded string (split on spaces). Print the top-5 most frequent words by transferring the map into a vector<pair<string,int>> and sorting by frequency descending.

Discuss: why unordered_map and not map here? When would you prefer map?

Exercise 3

Student roster with algorithms. Model a student roster using std::map<std::string, std::vector<int>> where the key is the student's name and the value is a list of assignment scores. Write functions to:

  • add a score for a student,
  • compute each student's average (use std::accumulate),
  • print the class ranked by average (highest first) — you will need to sort a derived vector<pair<string,double>>.

Use STL algorithms throughout; no hand-written index loops.
