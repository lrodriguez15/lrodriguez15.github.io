Algorithmic Thinking

A first course in structured programming with Python. You start by writing algorithms a hostile reader cannot misread, and finish by building a program that ingests a real dataset and argues a conclusion from it.

Python 3 algorithms Tec de Monterrey

How this course works

The algorithm comes before the code — always. Every exercise, lab and homework begins with the algorithm written by hand, before any editor is open. Your code is graded against your algorithm, not against a correct answer. The typing is not the hard part, and you should not find that out in November.

Class time is for writing and breaking programs, not for watching slides. Most sessions open with a program that fails, and the concept arrives as the fix.

On AI: you may use it to understand, never to produce. AI is not permitted in any class or laboratory session, and you will be asked to explain your own code out loud on project deliverables. The full policy is handed out in week 1.

Quick exam 1 — Tuesday 29 September

First 20 minutes of the session, Respondus LockDown Browser, Trinket for the code part. It covers week 1: the four properties of an algorithm, what input() returns, operator precedence, built-in functions, and a short program that requires calculations. 15 points multiple choice, 5 points one expression, 30 points an algorithm, 50 points its program. The rubric is below — it is not a secret.

Rubric (published)

Part Points What earns them
A1–A5 3 each Correct choice. No partial credit.
B 5 Correct value with the intermediate step shown. Correct value alone: 3. Intermediate step correct but final arithmetic wrong: 2.
C1 algorithm 30 INPUT:/OUTPUT: lines present and correct (10). Numbered steps that compute s before A (10). Every step is a single, unambiguous action a hostile reader could execute (10).
C2 program 50 Runs without error on 3 4 5 (15). Prints 6.0 or 6 (15). Inputs converted with float() (10). Implements the algorithm written in C1, not a different one (10).
Technical requirements −2 each Name comment · algorithm in multi-line comment · meaningful names · input prompts · labelled output

A program with no algorithm above it scores at most 50 — C1 is zero, C2 is graded. An algorithm with no program scores at most 50 the other way. Both halves are the exam.

Tools

  • Thonny — our environment. Python is built into the installer, so there is nothing else to set up, and its debugger shows variables changing one step at a time.
  • Trinket — Python in the browser. Exams use this, not Thonny.
  • PSeInt — Spanish-language pseudocode tool that draws the flowchart from your algorithm. Use it to check an algorithm you already wrote by hand — writing it there first just moves the thinking into a tool again.
